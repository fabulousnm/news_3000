# 当前提示词结构说明

本文说明生成器当前输出的提示词组成方式、三种现实平台 UI 模式，以及它们在数据文件中的标记。提示词由 `src/generate.py`、`src/render.py` 和 `src/ui_prompt_modes.py` 生成；具体 UI 参考模板见 `final/ui_reference_templates/`。

## 每组内容与提示词模式

生成器为每个内容组生成四个版本：`clean`、`subtle`、`strong` 和 `fabricated`。同一组的四个版本使用相同的 UI 提示词模式和模板，变化集中在内容字段及其变体上。

对于有兼容 UI 参考模板的组，模式配额为：

| 模式                       | CSV 类型编号                 | 配额  | 用途                             |
| ------------------------ | ------------------------:| ---:| ------------------------------ |
| 图+文 `image_text`         | 1                         | 60% | 附加本地模板图，并用普通自然语言要求生成完整页面截图。 |
| 长提示词 `long_quantified` | 有附图为 1；无附图为 2      | 30% | 以文字详细规定页面结构、区域比例、排版、字数密度和内容。 |
| 短提示词 `short_text`      | 3                         | 10% | 按具体模板写精简、独特的自然语言说明，并提供可见文案。 |

上述比例只针对有兼容模板的内容组。CSV 类型编号按实际输入判定：只要 `ui_reference_image` 非空就记为 `1`；没有附图的长提示词记为 `2`；短提示词记为 `3`。因此，长提示词模式若附带了模板图，CSV 类型编号仍是 `1`。模式按组分配，因此同组四个版本不会切换模式。

## 图+文提示词

图+文模式适用于有本地参考模板的组。提示词结构通常依次包括：

1. **参考图用途**：要求模型将随附图片作为 UI 视觉参考，复现页面风格和整体构图。
2. **完整页面要求**：要求模型参考附图生成完整页面截图，复现其构图、版位和比例。
3. **占位补全要求**：把内容灰块替换为给定文案或与主题有关的配图；明确留空的区域仍按模板处理。
4. **模板专属指令**：根据所用模板补充头像、关注/订阅按钮、评论、热搜列表、文章侧栏、推荐卡片或视频互动栏等细节。每张模板都有单独的规则，避免给不含相应控件的页面凭空添加内容。
5. **参考网址**：有匹配网址时附上网址，并说明“若无法访问该网站，则忽略此网址”；没有适用网址时不输出网址行。
6. **主体与画面文案**：给出媒体名称、标题/主题和逐项可见文字。互动数据带有含义标签，例如“评论数”“转发数”“点赞数”“浏览量”，避免只给模型一串无说明数字。
7. **用途与安全声明**：说明画面用于研究、媒体素养教育和合成数据评测，发布关系为模拟，并明确声明仅供模型理解、不可渲染为画面文字。

图+文模式的输入图片由调用端根据记录中的 `ui_reference_image` 附加。JSONL 中该字段是相对仓库路径；统一 CSV 的 `ui_reference_image` 列是当前电脑上的绝对路径。单独把路径写进提示词，不会自动把图片传给模型；调用端必须实际提供图像输入。

### 模板专属内容规则

模板指令按页面类型确定填充对象。例如：

- 微博帖子补账号头像、名称、关注按钮、正文、评论和互动数据；热搜页补话题标题和热度，并保持原排名。
- 小红书图文笔记补主图、作者信息、标题、正文、标签和互动数据；文字笔记不凭空增加配图。
- 微信文章模板分别处理纯文字文章、单主图文章、双图文章和公众号信息流卡片。
- 抖音视频模板补视频画面、发布者和右侧互动数；评论面板把评论内容限制在面板区域内。
- X、Facebook、Instagram 和 YouTube 模板分别补帖子媒体、互动栏、频道或推荐内容，同时保留各自页面构图。
- 新闻网页模板替换标题、正文及明确的插图占位；对广告栏、二维码、侧栏和页面导航分别保留或按模板规则处理。

所有图+文模板均要求忠实使用给定的标题、正文、标签和数字，不删改、重排或自行添加事实/数据；参考图片上的生图工具水印、压缩痕迹等后期叠加内容不属于目标 UI，不应复刻。

## 长提示词

长提示词由 `src/render.py` 组合，按需包含以下层次：

- 图像比例、载体类别及呈现方式，例如原生手机截图或新闻网页截图。
- 平台视觉风格、整体布局顺序，以及针对具体 layout 的 UI 细节。
- 虚构媒体、标题主题、地区和风险类别。
- 按页面区域组织的逐字文本块。区域名帮助定位内容，字段名和字段值说明要渲染的具体文字。
- 字体层级、文字密度、页面区域比例、可读性和边界约束。
- 对有变体的版本，说明内容中的预设差异必须照录，不能自动纠正或特别标记。
- 统一的逐字呈现和禁止无关文字等约束，最后附加用途与安全声明。

英文内容使用对应的英文段落结构；同样保留主题、逐字内容、版面规则和用途声明。

## 短提示词

短提示词用精简自然语言写明要 1:1 复刻的具体平台界面，并提供需要照录的可见文案。每个模板有独特描述，不附加模板图片。中文示例结构如下：

```text
请你1：1复刻微博移动端图文帖子界面截图，按下方内容呈现标题和正文。
正文：……
话题标签：……
评论数：…… 转发数：…… 点赞数：……
用途声明……（仅供模型理解，不要画进图片）
```

短提示词减少定量布局细节；统一 CSV 不提供 `ui_reference_image`，但会保留选择的模板标识及匹配网址供追溯。

## 用途声明

每条正式生成提示词末尾都有中文或英文用途声明。声明说明这是研究/教育/合成数据样稿，账号和发布关系为模拟；生成结果不应被当作真实新闻截图、官方通知或现实证据，也不应用于欺诈、冒充或误导。声明同时提醒模型不要加入真实隐私、账户凭据或可用于现实欺诈的信息，并明确要求不要把声明本身绘制在图中。

用途声明是给生成模型的上下文，不属于目标 UI 的可见内容，也不会作为一个画面字段写进 OCR 文本列表。

## 统一 CSV 的相关列

`final/news_rumor_prompts_unified.csv` 的最后三列记录提示词模式和图像参考：

| 列名                   | 含义                                              |
| -------------------- | ----------------------------------------------- |
| `prompt_type_code`   | `1` 有附加参考图，`2` 无附图的长提示词，`3` 短提示词。附图判断以 `ui_reference_image` 是否非空为准。 |
| `ui_reference_url`   | 与 UI 模板对应的网页地址；没有匹配网址时为空。                       |
| `ui_reference_image` | 本地 UI 参考模板绝对路径；短提示词和无参考模板的长提示词为空。                        |

JSONL 记录还包含 `ui_prompt_mode`、`ui_reference_template`、`ui_reference_url` 和 `ui_reference_image` 等字段，可用于追溯模式和模板选择。纯文本导出会附带模式和参考图元数据，方便复制提示词时知道是否还需提供图片。

当前统一 CSV 共 4,000 行：类型 `1` 有 2,236 行、类型 `2` 有 1,516 行、类型 `3` 有 248 行。类型 `1` 包含所有实际附加参考图的提示词；类型 `2` 是无附图的长提示词；类型 `3` 是短提示词。模式配额与 CSV 分类规则不同，因此三种类型的总行数不会按 60/30/10 平分。

## 代码入口

- `src/generate.py`：生成内容组和逐条提示词，追加安全声明，并导出 JSONL、CSV、TXT。
- `src/ui_prompt_modes.py`：模式比例、模板选择、参考网址、逐模板补全指令和图+文/短提示词构造。
- `src/ui_reference_urls.py`：参考网址定义。
- `src/render.py`：原有长提示词的版式和渲染细节。
- `tests/test_release_consistency.py`：验证提示词长度、模板覆盖、语义标签、网址回退指令和内容一致性。
